# Android TTF glyph snapshots

Captured on emulator-5556 by `FontSnapshotInstrumentation`. Reproduction, schema and limitations:
[tools/font-snapshots/README.md](../../../../../tools/font-snapshots/README.md).

Only 72 distinct characters: space, 자수봄날정민안녕, question mark, A–Z, a–z, 0–9.
Six gzip JSON files retain both outline-default and satin face roles for all 3 fonts.
Noto satin explicitly uses the bundled wght=400 XML family; outline uses the existing TTF default.
Android API/build, source font hashes and every captured file hash are pinned in `manifest.json`.
All TTF assets are already bundled OFL-1.1 fonts; complete notices are retained beside these snapshots.
No private design files are used. PES files are generated by the app specifically for this test.

Snapshot total: **784301 gzip bytes**, **7005315 JSON bytes**.
Captured files including 6 PES, cases, completion marker, gzip object JSON and OFL notices: **865202 bytes** (excludes this README and manifest itself).

JVM regression: `./gradlew :engine:test --tests '*AndroidFontSnapshotTest'`.
It reconstructs centerlines from the binary snapshots, measures widths from the captured contours,
and prepares text with the shared engine APIs. Expected PES comes from actual app `renderLettering`,
with explicit default sewing settings. Two fonts × two Hangul strings and one Latin string = 6 captured cases.
The cases record the app-selected automatic style. Default tests assert all 6 object JSON payloads
and 4 Hangul satin PES files. The extra 2 FILL PES cases are opt-in diagnostics; Noto Thin
Ab12 at 15mm showed downstream FILL nondeterminism (2934 vs 2942 bytes) with exact prepared
object JSON. Jua Latin initially matched. See the tools README for evidence and the strict
`MYEMBRO_SNAPSHOT_FILL_PARITY=1` diagnostic command. FILL parity is unconfirmed.

Coverage is finite. Uncaptured glyphs, other axes/weights, and other Android/Skia revisions are unconfirmed.
No Java2D/FreeType extraction equivalence or full 2,350-character Hangul coverage is implied.
