# Photo-filter original-output goldens

Generated by [the independent upstream runner](../../../../../tools/photo-filter-oracle/README.md)
from the research pins in `docs/photo-filters.md` (`582f447`). The fixture set has
**39 cases**: 12 synthetic patterns plus the repository's own launcher artwork,
each with long edge **128/192/256px**. Synthetic patterns comprise seven L and
five RGB inputs; the narrow RGB raster is 3px wide with the requested long edge.
No private photos, downloaded illustrations, or user embroidery files are used.

Originals and source licenses (the Python implementations are not bundled):

- [scikit-image 0.25.2 thresholding.py](https://github.com/scikit-image/scikit-image/blob/e8a42ba85aaf5fd9322ef9ca51bc21063b22fcae/skimage/filters/thresholding.py): BSD-2-Clause;
  `threshold_otsu(image, nbins=256, hist=None)`, 2-D uint8, first maximum and constant-image return unchanged.
- [Pillow 11.3.0 ImageOps.py](https://github.com/python-pillow/Pillow/blob/89f1f4626a2aaf5f3d5ca6437f41def2998fbe09/src/PIL/ImageOps.py): [MIT-CMU](https://github.com/python-pillow/Pillow/blob/89f1f4626a2aaf5f3d5ca6437f41def2998fbe09/LICENSE);
  `autocontrast(image, cutoff=0, ignore=None, mask=None, preserve_tone=False)`.
- NumPy 2.2.4 and SciPy 1.15.2 are pinned, together with all transitive wheels.
  Exact commits, package versions, source hashes and download hashes are in
  `provenance.json` and the runner's lock files.

Each case contains:

| File | Meaning |
|---|---|
| `input.png` | Exact L/RGB bytes supplied to original autocontrast. |
| `otsu-input.png` | Exact 2-D uint8 bytes supplied to original Otsu. |
| `otsu-mask.png` | L PNG: **input ≤ threshold is ink 0**, other pixels are background 255. |
| `autocontrast.png` | Original output, same L/RGB mode as input. |
| `expected.json` | Threshold/dtype; original histogram, cumulative weights, means and between-class variance when computed; captured autocontrast histogram/LUT; decoded pixel SHA-256 values. |

For RGB Otsu inputs, preparation uses the **existing app** integer BT.709 adapter
`(2126*r + 7152*g + 722*b + 5000)//10000`. This is not an Otsu default or a new
filter algorithm. Kotlin parity tests should start with the stored `otsu-input.png`
so conversion is independently testable. The artwork is the repository's
GPL-3.0-or-later `docs/images/launcher-icon-artwork.png`, resized to RGB with pinned
Pillow LANCZOS. Comparing resamplers or image decoders is outside filter parity.
All committed PNGs are opaque; alpha compositing is outside these fixtures.

Use `ImageIO` raster samples for L PNG bytes: `getRGB` on TYPE_BYTE_GRAY performs
a color-space transform. RGB bytes are row-major interleaved R/G/B. All exact
payload hashes are recorded, independently of PNG compression. `manifest.json`
also hashes all 196 generated payload/JSON/provenance files (not itself or this README).

The three constant inputs intentionally produce all-ink masks under `<=`, even
constant white. A two-level 32/224 tie returns threshold 32. Do not reverse
the documented polarity or silently replace the original constant/tie behavior.
Handling an empty/solid design in UI/tracing is a separate integration decision.

The local JVM integrity test checks hashes and encoding only; the Kotlin ports
must add their own exact-output comparisons. These fixtures follow GPL-3.0-or-later,
like the runner and repository artwork. No upstream implementation is copied here.
