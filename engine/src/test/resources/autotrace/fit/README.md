# AutoTrace 0.31.10 centerline fit goldens

Upstream: https://github.com/autotrace/autotrace/tree/1a232b27818a46a05cd25edec09e2f77c4e9ac01
`src/fit.c` GPL-2.0-or-later, Copyright (C) 1992 Free Software Foundation, Inc.
Full license: ../thinning/COPYING. Supplementary curve/spline/vector functions use the same project license.

Five existing public/synthetic PGM inputs from ../thinning × grayscale/RGB = ten cases.
No private embroidery or local sewout input is included. Noto Sans KR source license is
../thinning/OFL.txt. Original C runs thinning → ordered centerlines → fitted_splines,
new_fitting_opts defaults with centerline=TRUE, preserve_width=FALSE. The adapter only calls
upstream; no fitting algorithm is implemented in the reference caller.

`manifest.json` records the pinned source, all source/tool/input/output hashes, compiler and
flags. JSON records path order/open/orientation, each polynomial degree and all four xyz
control points (`%.9g`, sufficient to round-trip gfloat). Kotlin assertions compare **float
bits**, not tolerance, and repeat each fit. Fixtures exercise lines, branches, cyclic fitting,
filtering, subdivision and cubics; they do not prove equality for every possible input.

Regenerate (existing headers/runtime; no dependency installation):

```sh
python3 tools/autotrace/generate-fit-goldens.py /tmp/myembro-autotrace-reference --glib-prefix /tmp/myembro-autotrace-build/glib --verify
JAVA_HOME=/home/gosh2/.jdks/jdk-17.0.20.1+1 ./gradlew :engine:test --tests '*AutoTraceFitTest'
```

Original sources must be the clean pinned checkout. `--verify` asserts generated bytes equal
committed golden bytes. Normal CI only runs Kotlin and reads these frozen goldens, never C.
