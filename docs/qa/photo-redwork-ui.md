# S4 photo redwork UI — smoke 1

## User flow

Home → Start new project/Create → From photo (quick start also connected).
1. System photo picker (OpenDocument), EXIF orientation, pinch/pan crop at default hoop aspect ratio.
2. Actual generated monochrome running preview. Detail is the only adjustment, changing only input sampling 128/192/256.
3. SewoutCheck pass/block badge, needle count, estimated time → editor / send.

- Detail is a product input-sampling choice, not labeled an Ink/Stitch parameter.
  Wu 2 colors, Potrace, and running/S1 settings retain engine defaults. No density/lock/stitch-type UI.
- Guide users to place the photo's top-left marker on background. Add no new automatic background estimation rule.
- All UI colors are MaterialTheme tokens. Fixed RGB is only for actual thread colors and compositing onto white paper for RGB input.
- Default hoop/machine/PES version come from app settings. Use shared mm/in formatters.
- Generation runs on Default, photo decode/save on IO. Discard stale results through work versions/cancellation;
  block sending during changes/errors/checks. Blocked results can still be opened in the editor for correction.
- Pass generated StitchObject to the editor at its original hoop position; reuse existing dirty-replacement confirmation.
  Original photo/crop currently exist only in the ViewModel session; no regenerable photo-object storage in .myembro.
- Sending saves atomically with a new ASCII numbered filename (`photo_linework_2.pes`, next number on collision), then
  invokes existing library preflight/USB flow. Do not overwrite existing user files.
- Code verified matching 30 ko/en photo-string keys.
