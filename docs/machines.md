# 미싱 프로필

확인일: 2026-10-22. 브라더 공식 자료(미국·캐나다) 기준이며 기본 기종은 **Brother SE400**입니다.
공식 사양 확인과 Android 실기 검증은 구분합니다. 앱의 내보내기 형식은 PES입니다.

| 기종 | 최대 단일 자수 영역 | 확인된 후프 (가로×세로) | 전송 |
| --- | --- | --- | --- |
| SE400 | 100×100mm | 100×100, 별매 60×20, 재배치형 100×170 | USB 케이블 → PC의 이동식 디스크 |
| SE600 | 100×100mm | 100×100, 별매 60×20, 재배치형 100×170 | USB 메모리 |
| SE700 | 100×100mm | 100×100, 별매 SA431 60×20, 재배치형 SA434 100×170 | USB 메모리 / 브라더 무선 전송 |

큰 재배치 후프는 원단을 다시 끼우지 않고 여러 위치에 수놓는 용도이며 단일 봉제 영역을
늘리지 않습니다. 기본 후프는 100×100mm (4×4in)입니다. 모든 프레임을 선택할 수 있으며
선택 기종에서 확인되지 않은 프레임은 ‘이 미싱에서 지원하지 않음 — 수놓기 전 확인’을 표시합니다.

### SA431·SA434 확인값

앱은 **가로×세로** 순서입니다. 브라더 액세서리 표의 H×W를 그대로 가로×세로로 읽지 않습니다.

| 프레임 | 공식 H×W | 앱 가로×세로 | 공식 인치(호칭) | 호환 확인 | 위치 개수·오프셋 |
| --- | --- | --- | --- | --- | --- |
| SA431 / EF61 | 20×60mm | 60×20mm | 2½×1in | SE400·SE600·SE700 | 해당 없음 |
| SA434 / EF71 | 170×100mm | 100×170mm | 4×6¾in | SE400·SE600·SE700 | **미확인** |

출처: [SA431 공식 제품 페이지](https://www.brother-usa.com/p/hoops-stabilizers/SA431),
[SA431 공식 2×6cm 표기](https://www.brother.com.br/products/sa431),
[SA434 공식 제품 페이지](https://www.brother-usa.com/p/hoops-stabilizers/SA434),
[SE700 공식 액세서리 목록](https://support.brother.com/g/b/sp/colist.aspx?c=us_ot&cao=hfemba&lang=en&prod=hf_se700eus),
[단일 위치 최대 4×4 공식 안내](https://help.brother-usa.com/app/answers/detail/a_id/72260/~/available-hoop-sizes).
미국 제품 페이지의 호환 목록에서 SE400·SE600을, SE700 액세서리 목록에서 SA431·SA434를 확인했습니다.
매뉴얼의 미터법 치수와 인치 호칭은 정확한 환산값이 아닙니다. 예를 들어 20mm를 실제 1in로
변환하지 않습니다. 공식 후프 이름에는 호칭을, 도안 실측값에는 25.4mm/in의 실제 변환을 씁니다.
SA434의 ‘보통 3위치’ 또는 ±35mm는 공식 수치로 확인되지 않아 프로필에 넣지 않습니다.

## 상태와 통합 API

`ui/machines/MachineProfile.kt`가 출처 URL과 확인된 값만 보관합니다. 영역은 engine의
`HoopSpec`을 그대로 사용하며 단위는 0.1mm입니다. `null`/빈 제한 목록은 무제한이 아닌 미확인입니다.
직접 입력한 다른 기종은 프로필이 `null`이며 SE400의 확인된 기능을 상속하지 않습니다.

```kotlin
val preferences = SettingsPreferences(context)
val settings = preferences.read()
val profile = settings.machineProfile      // MachineProfile?; 미확인 기종은 null
val hoops = preferences.editorHoops()      // List<engine.edit.HoopSpec>; 경고 선택 가능한 전체 프리셋
val initial = preferences.defaultEditorHoop() // HoopSpec; 선택한 프레임의 실제 크기
val dispose = preferences.observe { /* 기종/기본 후프 변경 시 새 목록 조회 */ }
// 화면 또는 ViewModel 폐기 시 dispose()
```

- 기종 변경 시 기본 후프를 100×100으로 함께 저장합니다. 지원하지 않는 프레임도 선택·유지합니다. 미설정/빈 기종은 SE400으로 전환하고 기존의 직접 입력한 기종 이름은 유지합니다.
- 설정·홈·목록·뷰어는 같은 SharedPreferences 변경을 관찰합니다. 뷰어에서도 지원되지 않는 후프를 경고와 함께 선택할 수 있습니다. 목록 배지는 현재 프로필과 실제 도안 경계를 비교합니다.
- 목록/뷰어의 `profile.fits(bounds)`는 **도안 크기** 판정입니다. 편집기에서 배치한 오브젝트는
  기존 engine의 `Bounds.outside(project.hoop)`로 위치까지 판정해야 합니다.
- **통합 담당**: 편집기 후프 메뉴를 `editorHoops()`로 바꾸고 새 프로젝트에 `defaultEditorHoop()`를
  사용하세요. 기종 변경으로 기존 편집 도안이 초과하더라도 자동 축소하거나 삭제하지 말고
  기존 초과 표시를 유지하세요. 미확인 기종은 수동 설정 안내가 필요합니다.
  편집기와 MainActivity 소스는 이 커밋에서 변경하지 않았습니다.

## 생성 동선

- 홈 새 프로젝트 카드와 만들기 탭은 동일한 `NewProjectSheet`를 엽니다. 빈 후프 선택 시
  선택 가능한 후프가 하나면 별도 후프 질문 없이 `onBlank(H100)`으로 시작합니다.
- `NewProjectSheet(onBlank, onFromDesign, onFromText, hoops)`는 호스트 콜백을 제공합니다.
  **통합 담당**은 `HomeScreen.onCreateFromDesign`을 도안 선택 → 선택 파일로 편집기 진입에
  연결하세요. 새 전용 `DesignPickerScreen(onSelect, onBack)`의 연결 코드는
  [디자인 시스템의 통합 메모](design-system.md#전용-도안-picker와-펼친-화면)에 있습니다.
  기본 콜백은 기존 `onOpenLibrary`를 사용하므로 호스트에서 생성 전용 경로를 지정해야 합니다.
- 레터링 진입점은 `HomeScreen(letteringAvailable = true, onLettering = { ... })`로 실제 화면에
  연결할 때만 노출합니다. 기본값은 비노출입니다.
- 홈 갤러리는 실제 PES 샘플만 표시하며 빈 캔버스 템플릿은 제거했습니다.
  샘플은 기존 `onOpenRecent(file)`로 뷰어에서 열고 편집 버튼으로 프로젝트를 만듭니다.
- 도안 목록은 관리 전용입니다. 만들기 버튼은 제거했습니다.

### 포맷/커뮤니티 근거와 구현 선택

- [pyembroidery 1.5.1 PesWriter.py](https://github.com/EmbroidePy/pyembroidery/blob/1.5.1/pyembroidery/PesWriter.py)는
  최소 v1과 전체 v6 경로를 제공합니다. v6는 `CEmbOne`/`CSewSeg`, 사용자 실 표,
  PEC 데이터 및 추가 색상 정보를 씁니다. 이는 구현 근거이며 SE400 인증 자료가 아닙니다.
- 커뮤니티 역공학 자료 [EduTech Wiki: PES](https://edutechwiki.unige.ch/en/Embroidery_format_PES)는
  PES 편집 정보와 PEC 봉제 데이터의 역할, 버전 간 PEC 호환성 및 v4 이후 추가 정보를 설명합니다.
  이것만으로 특정 SE400 펌웨어가 v6를 받는다고 보장할 수 없습니다.
- myembro v6는 위 pyembroidery 버전의 전체 헤더/봉제 객체 구조를 포팅했습니다.
  v1/v6 모두 48×38 1비트 전체/색상별 PEC 썸네일을 기록합니다.
  PEC의 고유 실 64개·STOP 포함 255블록은 **라이터 포맷 제한**이며 SE400 색상 제한으로 취급하지 않습니다.
- v6의 저장 후프 기본값은 pyembroidery와 같은 100×100mm입니다. 실제 100×100 초과 도안은
  이 헤더만으로 적합해지지 않으므로 Preflight 경고를 확인해야 합니다.

### 통합 담당: 내보내기 전에 검사하고 버전을 선택하기

엔진 `io.PesWriteSettings`와 `export.MachineProfile`은 앱 설정/UI와 독립적입니다.
기존 앱 `ui.machines.MachineProfile`과 동명이라 둘을 함께 쓰는 곳은 import alias를 사용하세요.
앱의 기본 출력 버전 선택 UI·설정 저장·경고 표시는 이번 변경에 연결하지 않았습니다.

```kotlin
val settings = PesWriteSettings(PesVersion.V6) // 앱에서 저장한 선택값; 미지정 기본값은 기존 V1
val warnings: List<String> = Preflight.check(pattern, "design.pes", MachineProfile.SE400)
// warnings를 한국어로 표시한 후 내보내기 진행 여부를 사용자가 선택하도록 연결
val bytes = PesWriter.write(pattern, settings) // 또는 PesWriter.writeV6(pattern)
// 실제 저장 바이트의 경계/명령을 확인하려면 PesReader.read(bytes)도 검사 가능
```

`Preflight.check`는 첫 END까지 STITCH 수와 이동을 포함한 크기, 파일명 권장 문자·확장자·폴더,
전송 묶음의 도안 수를 검사해 한국어 경고 목록을 반환합니다. 자동 축소·삭제·파일명 변환은 하지
않습니다. `patternCount`는 기존 도안을 포함한 대상 묶음 수입니다. 내부 메모리 저장일 때만
`destination = ExportDestination.INTERNAL_MEMORY, totalBytes = ...`로 전체 사용량을 넘기세요.
PC 전송의 파일 용량에 512KB를 적용하지 않습니다. 미확인 색상 수·PES 이름 길이·버전 지원은
판정하지 않습니다. 프로젝트의 후프 상대 위치 초과는 기존 `Bounds.outside(project.hoop)`도
함께 확인해야 합니다.

`PesExport.prepare(data, fileName, settings)`는 PEC/DST 변환에 선택 버전을 적용하지만,
이미 PES인 파일은 편집 정보를 보존하도록 바이트 그대로 전달합니다. PES를 v6로 다시 만들려면
`PatternReader.read` 후 `PesWriter.writeV6`를 명시적으로 호출하세요. 고수준 벡터 편집 객체를
복원하는 변환은 아닙니다.

### 실제 SE400 확인 필요

엔진 왕복과 pyembroidery 교차 검증은 통과했지만 **SE400 실기 인식/봉제는 미검증**입니다.
같은 작은 100×100 이내 도안을 v1/v6로 각각 전송해 목록 표시·방향·실 순서·STOP·점프·트림을
확인해야 합니다. 특히 파일 TRIM 명령의 보존이 SE400의 자동 실 자르기 동작을 뜻하지 않습니다.
실기 확인 전에는 기본 출력 버전을 강제로 v6로 바꾸지 않습니다.

## 인치 포맷터와 위치 데이터 통합 메모

`ui.format.Dimensions.length/size`는 실측 mm→in을 25.4로 환산합니다. 정확한 ¼·½·¾은 분수로,
나머지는 소수 한 자리 HALF_UP으로 표시합니다. `hoopSize`는 확인된 제조사 호칭을 사용합니다.
홈·새 프로젝트·설정·뷰어·도안 목록에 적용했으며 `DimensionsTest`가 환산/반올림을 검사합니다.
**embro-editor**: X/Y에는 `length`, 객체 크기에는 `size`를 사용하세요.
**embro-letter**: 글자 높이에 `length`를 사용하세요. 이 두 담당 화면 파일은 변경하지 않았습니다.

`engine.edit.HoopSpec.positions: List<Bounds>`만 데이터 계약으로 추가했습니다. 좌표는 프로젝트 중심,
0.1mm 단위이며 각 Bounds는 위치별 봉제 사각형입니다. 빈 목록은 검증된 위치 배치가 없다는 뜻입니다.
**embro-model**: 확인된 위치만 SewingPosition으로 변환하고 ProjectJson의 위치 왕복을 연결하세요.
현재 SA434의 위치 목록은 비어 있으며 이 값으로 자동 분할하지 마세요. 기존 프로젝트 API와 생성자는
기본값으로 호환됩니다. 위치 분할 로직과 편집기 파일은 이 커밋에서 수정하지 않았습니다.

## 사용자 정의 프레임과 자유 기종 (추가)

설정에서 프레임 이름·가로·세로를 mm/in으로 입력하고 저장·편집·삭제할 수 있습니다.
인치 입력도 **25.4mm/in**, 0.1mm HALF_UP으로 저장합니다. UI 입력 범위(0.1~10,000mm)는
기종 사양이 아닌 입력 오류 방지 범위입니다. 설정 저장소는 ID로 기본 프레임을 참조하며 삭제하면
100×100으로 복귀합니다. 기존 `.myembro` 프로젝트에 저장된 크기는 변경하지 않습니다.

`MachineProfiles.FREE`는 ‘기타(자유)’입니다. 미확인 기능을 지원한다고 주장하지 않으며 기종의
면적·땀수·파일 수 제한을 강제하지 않습니다. 선택한 실제 프레임 경계와 호환 미확인 경고는 유지합니다.
사용자 정의 프레임과 미지원 프리셋은 모두 선택할 수 있으며, 알려진 기종의 봉제 영역은 늘리지 않습니다.

## SE400 USB 직접 연결 — 사용자 실측 (2026-10-23)

다음은 공식 브라더 매뉴얼이 아닌 **사용자가 제공한 SE400 + 삼성 폴드7 실측 사실**입니다.
다른 Android 기기나 다른 미싱으로 일반화하지 않습니다.

- SE400의 USB-B 포트는 USB 대용량 저장장치로 동작하며 Windows에서는 정상적으로 파일을 복사합니다.
- 폴드7 Android는 해당 볼륨을 마운트하지 않아 SAF 폴더 선택기에 나타나지 않습니다.
- 별도 유료 앱에서는 볼륨명 **NO NAME**, 파일시스템 **Microsoft FAT**, 표시 용량 **476.0 kB**로
  인식됩니다. 사용자가 FAT12 램디스크로 보고했습니다. 표시 용량만으로 형식을 추정하여 쓰지 않고
  myembro는 실제 BPB와 데이터 클러스터 수로 FAT12인지 확인합니다.
- 미싱 전원을 끄면 디스크 파일이 지워지는 **휘발성 램디스크**입니다.
- 실제 VID/PID, 논리 섹터 크기, BPB 세부값, MBR 유무, 복수 LUN 여부는 **미확인**입니다.
  myembro 직접 쓰기 후 SE400의 도안 목록 인식·봉제와 폴드7 권한/연결 동작은 아직 **실기 미검증**입니다.
  위 실측은 별도 앱/Windows의 인식 결과이며 myembro 실기 성공 보고가 아닙니다.

구현은 `engine/fat12`의 순수 Kotlin 파일시스템과 `usb/DirectUsbAccess`의 libaums 0.10.0
BOT/SCSI 블록 드라이버를 결합합니다. SAF 드라이브가 없을 때 연결된 class 8 / subclass 6 /
protocol 80 인터페이스를 ‘SE400 직접 연결’ 드라이브로 노출합니다. 실제 쓰기는 USB 권한 허용 후,
FAT12 BPB 확인에 성공한 볼륨에서만 수행합니다. 파일명은 대문자 ASCII 8.3으로 생성하고, 중복은
`_1`, `_2` 등으로 피하며 LFN을 생성하지 않습니다. 포맷·파티션 생성·자동 복구 API는 없습니다.
FAT 사본을 모두 갱신하고 각 쓰기와 최종 파일을 물리 읽기로 비교합니다.

공간 또는 루트 엔트리가 부족하면 **쓰기 전에** 중단하고 기존 `.PES` 목록을 보여줍니다.
기본 선택은 없으며 사용자가 체크한 파일의 삭제를 확인해야만 재시도합니다. 볼륨 메타데이터가
확인 대화상자 이후 바뀌면 삭제를 거부합니다. 자동 삭제·이름이 같은 기존 파일 덮어쓰기는 하지 않습니다.

통합 구조·검증 명령·실기 확인 순서는 [SE400 직접 USB 구현 메모](se400-direct-usb.md)에 있습니다.

### 2026-10-23 추가 실측: 펌웨어가 다시 만드는 RAM 디스크와 alpha14 진단

사용자는 SE400을 껐다 켜면 파일이 비워지고, Windows에서 포맷하거나 볼륨 이름을 지정해도
다시 켜면 원래 디스크 상태로 돌아간다고 보고했습니다. 부트섹터·FAT가 전원 투입 때 펌웨어에
의해 합성되는 RAM 디스크로 취급합니다. 이 동작은 **사용자 실측**이며, 실제 OEM·점프·미디어
바이트와 BPB/READ CAPACITY 차이는 아직 **미확인**입니다. myembro는 계속 **포맷·볼륨명 변경·
부트섹터 수정·자동 복구를 수행하지 않습니다**.

실기에서 `MBR partition out of device bounds` 오류가 보고되어 다음처럼 처리합니다.

- 슈퍼플로피 마운트 실패 이유와 MBR 실패 이유를 모두 보존합니다. `0xEB`/`0xE9` 점프와 그럴듯한
  BPB가 있으면 446–509바이트를 MBR로 해석하지 않습니다. MBR 첫 유효 엔트리는 boot flag
  `0`/`0x80`, type `0x01`(FAT12), 장치 안의 유효한 시작과 양수 길이를 만족해야 합니다.
  길이가 실제 남은 장치 범위를 넘으면 그 범위로 제한하고 경고합니다.
- 비표준 점프·미디어 바이트와 BPB/FAT 미디어 불일치는 경고로 남깁니다. OEM은 검증 조건으로
  사용하지 않습니다. BPB 전체 섹터가 실제 장치/파티션보다 크면 접근 범위를 작은 쪽으로 제한합니다.
  원래 BPB는 쓰지 않으며, 선언된 레이아웃의 FAT12 클러스터 수·FAT 크기 및 실제 장치 안의
  메타데이터·클러스터 범위, FAT 사본 일치·체인 검사는 계속 적용합니다.
- USB 실패 다이얼로그의 **진단 정보 복사 / 공유**는 기존 SCSI 초기화에서 수신한 INQUIRY
  vendor/product/revision, READ CAPACITY 원시값·블록 수·블록 크기, sector0 처음 512바이트 hex,
  BPB 숫자 필드와 MBR 후보 엔트리를 텍스트로 제공합니다. 읽지 못한 값은 미확인으로 표시합니다.
  별도 진단 쓰기 명령을 보내지 않습니다. 사용자 텍스트 공유 후 실제 비표준 필드의 원인을 확인합니다.

### alpha20 실기 진단: MBR 길이 불일치

사용자 진단에서 sector0는 BPB 없는 MBR이며, 첫 파티션은 **boot=0x80, type=0x01,
start=32(0x20), sectors=987(0x3DB)** 입니다. READ CAPACITY는 **lastLBA=987,
blockCount=988**로 확인되었습니다. 파티션의 선언상 끝 1019는 실제 장치 끝 988을 넘습니다.
이는 사용자 실기 진단값이며, LBA 32의 실제 BPB 내용은 아직 **미확인**입니다.

MBR 길이를 `988−32=956`섹터로 제한하고 경고합니다. BPB의 total sectors도 이 범위보다
크면 줄여 접근하며, 메타데이터·완전한 데이터 클러스터·기존 파일 체인이 범위 안에 들어오지
않으면 차단합니다. MBR의 start는 여전히 `0 < start < blockCount`여야 합니다.
MBR·BPB·볼륨명을 고쳐 쓰거나 포맷하지 않습니다.

다음 실패 진단에는 **partition start sector (LBA 32)**의 처음 512바이트 hex와 BPB 해석을
sector0와 별도로 표시합니다. 마운트에서 이미 읽은 바이트를 파싱 전에 보관하므로 추가 USB 읽기
명령 없이 BPB 파싱 실패 원인도 분석할 수 있습니다. 읽기 자체가 실패한 값은 미확인으로 표시합니다.

## Sew-out Check: 자르기·속도 사실과 미확인 구분 (2026-10-23)

‘SE400/SE600에 자동 실 자르기가 없다’고 일괄 단정하면 부정확합니다. 다음 두 동작을 구분합니다.

| 동작 | SE400 | SE600 | SE700 |
| --- | --- | --- | --- |
| 색 단계 끝 자동 자르기 | 설정하면 동작, p.140 | 설정하면 동작, p.66 | 설정하면 동작, p.70 |
| 색 내부 점프 연결실 | 구체적 자동 절단 조건 미확인 | 수동 정리 안내 p.66 | 수동 정리 안내 p.71 |
| PES TRIM만으로 점프 자동 절단 보장 | 미확인 | 미확인 | 미확인 |
| 최대 자수 속도 | 이번 조사 미확인 | 이번 조사 미확인 | 400 SPM, p.96 |

출처는 [SE400 공식 매뉴얼](https://download.brother.com/welcome/doch000184/885v31_v32_v33_om04en.pdf),
[SE600 공식 매뉴얼](https://download.brother.com/welcome/doch101011/888m20_om02en.pdf),
[SE700 공식 매뉴얼](https://download.brother.com/welcome/doch102582/888p10_om01en.pdf)의 인쇄 페이지입니다.
색 단계 끝 절단은 설정에 따른다고 명시됩니다. SE600/SE700은 같은 색 안의 남은 연결실을
자르라고 별도로 안내합니다. 이 문구를 ‘점프 때마다 기계가 멈춘다’ 또는 ‘커터 자체가 없다’로
확대하지 않습니다. 현재 엔진은 점프 자동 절단 기능의 세부 조건을 미확인으로 두고, 공식 수동
정리 안내가 있는 경우 손 작업을 계획합니다. SE400은 구체적 점프 조건이 미확인이므로 조건부
수동 확인으로 표시합니다. 실제 기종 설정은 사용자가 입력해야 합니다.

SE700의 p.96 사양 표는 재봉 속도 70~710과 **최대 자수 속도 400**을 구분합니다. SE400/SE600의
최대 자수 SPM을 이 값이나 타 기종 값으로 추정해 확인값으로 저장하지 않았습니다. 미확인 기종에
계획용 가정 속도를 쓰면 근거도 ASSUMED로 반환합니다. 밑실 한 개의 미터 수는 세 기종 모두
실 굵기/감긴 양을 확인하지 못해 미확인입니다. 파일당 용량·PES 지원 버전·최대 색 수도 기존의
미확인 상태를 유지합니다. 내부 메모리 전체 용량을 파일당 한계로 적용하지 않습니다.

관련 순수 JVM API와 규칙·추정식은 [sewout-check.md](sewout-check.md)에 있습니다. 이 프로필은
앱 UI 프로필과 독립적이며, UI 연결은 embro-editor의 별도 작업입니다.
