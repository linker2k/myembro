## Actual call chain and algorithm

1. `PFMSketchLinesBasic` extends `AbstractSketchPFM`, which extends `AbstractDarkestPFM` → `AbstractPFMImage` → `AbstractPFM`. The important active search is `PlottingTools.findDarkestLine` → `SimpleLineSampler`; do **not** port the deprecated `AbstractDarkestPFM.findDarkestLine/forAvailableEndPoints` instead. In particular, that older endpoint code uses `ceil`, whereas the active sampler truncates offsets before adding the start coordinate. Sources: [PFMSketchLinesBasic.java:5–24](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/PFMSketchLinesBasic.java#L5-L24), [PlottingTools.java:438–454](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/plotting/PlottingTools.java#L438-L454), [AbstractDarkestPFM.java:165–194](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/AbstractDarkestPFM.java#L165-L194).
2. Setup swaps reversed length, squiggle, radius, and erase bounds; records initial average luminance; installs `PixelTargetDarkestArea` and canvas rescale mode. Pixel storage is ARGBY only when the radius is constant and rendered pen width is exactly `1F`; otherwise it uses the additive composite backend. [AbstractSketchPFM.java:51–91](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/AbstractSketchPFM.java#L51-L91).
3. Restart at the darkest pixel **inside the darkest-average tile**, not necessarily the globally darkest pixel. Tile nominal dimensions are `max(10, width/200)` and `max(10, height/200)`. Tile counts use integer division with a minimum of 1; the last tile absorbs the remainder. Only plottable pixels count. Tile averages are cast to integers for selection; strict comparisons keep the first tie in x-major/y-minor traversal. Luminance changes update cached averages and invalidate the selected-pixel cache when that pixel changes. [PixelTargetDarkestArea.java:30–91,94–161](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/image/PixelTargetDarkestArea.java#L30-L161).
4. For each next segment, enable shading only if enabled and `shadingThreshold < lumProgress`. Draw a random start angle, then a random maximum length; call the sampler. With default settings it tests 20 angular directions across 360°. Shading tests 2 directions. Full-circle/unlimited mode can enumerate Bresenham circle endpoints instead. Endpoint coordinates truncate each trigonometric offset toward zero. [PFMSketchLinesBasic.java:17–24](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/PFMSketchLinesBasic.java#L17-L24), [SimpleLineSampler.java:50–90](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/helpers/SimpleLineSampler.java#L50-L90).
5. Traverse candidates with Bresenham. Score every valid prefix using cumulative luminance divided by pixel count, accepting only when `pixelCount > minPixelCount`; choose the strictly lower score, retaining the first tie. A chosen endpoint can precede the candidate endpoint. Horizontal/vertical candidates receive `+1` to the luminance sum before sampling. Invalid pixels follow the clip/edge handling in the scorer; preserve its early-result behavior rather than substitute geometric line clipping. [LuminanceTestLine.java:27–62](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/helpers/LuminanceTestLine.java#L27-L62), [LuminanceTest.java:20–35](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/helpers/LuminanceTest.java#L20-L35), [BresenhamHelper.java:182–204,276–314](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/helpers/BresenhamHelper.java#L182-L314).
6. Emit accepted lines and brighten their coverage while sampling the **unchanged reference image** for color. For start luminance `L`, `x=L/255`, `y=tone*x³+(1-tone)*x`; interpolate erase amount and stroke width from `y`, truncating erase to integer. The cubic is confirmed in [EasingUtils.java:59–61](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/geom/easing/EasingUtils.java#L59-L61). The raster backend either adds RGB with clamping or uses AWT stroke/compositing. [AbstractSketchPFM.java:240–264](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/AbstractSketchPFM.java#L240-L264), [PFMRenderPipe.java:53–102,127–152](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/helpers/PFMRenderPipe.java#L53-L152).
7. Squiggles are connected segment sequences, not independent stitches. Default pen lifting restarts after the squiggle limit or brightness tests after the minimum. Missing results whiten the isolated current pixel; 1000 consecutive failures stop. Progress can stop earlier through luminance density, maximum line count, cancellation, or the task callback. Colour Match hooks can return after one squiggle; they do not establish a Free color-separation algorithm. [AbstractSketchPFM.java:99–210](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/AbstractSketchPFM.java#L99-L210).

## Randomness and reproducibility

`PlottingTools` constructs `java.util.Random` with seed `0`, and `setRandomSeed` reseeds it: [PlottingTools.java:44–70,670–685](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/plotting/PlottingTools.java#L44-L70). The interface uses bounded Java Random methods, handles equal bounds without consuming a draw, and swaps reversed bounds: [IPlottingTools.java:259–322](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/api/IPlottingTools.java#L259-L322). Default maximum-length draws are upper-exclusive: `2..39`; the angle interval is `[-72,-52)`.

Proposed parity contract: same input raster, dimensions, effective settings, pen width, clipping, rescale mode, seed, ordered calls, and termination callback. Preserve Java bounded RNG behavior; `kotlin.random.Random(seed)` is not a replacement. Android compatibility of the newer bounded Java methods needs review before porting; reproduce their arithmetic without changing draw consumption if unavailable. Keep one mutable sampler/cache/RNG per task: `SimpleLineSampler` explicitly is not thread safe (:8–10). Parallelize separate jobs only.

Determinism across JVM/Android is **unconfirmed** until tested. Floating-point interpolation, trigonometric truncation, pixel luminance rounding, incremental averages, and rasterization can change the first tied winner and all subsequent paths. ARGBY updates perceived luminance on RGB mutation ([PixelDataARGBY.java:39–64](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/image/PixelDataARGBY.java#L39-L64)); its helper formula and raw-average bookkeeping must be included in the later parity review rather than replaced with myembro's grayscale filter by assumption.

## Kotlin port boundary and dependencies

The upstream application targets Java `19`; declares JavaFX base/controls/FXML/graphics/Swing/web, plus desktop libraries including imgscalr, JTS, Batik, JHLabs and others ([build.gradle:3–52](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/build.gradle#L3-L52)). These application dependencies are not all requirements of the line algorithm. Direct desktop coupling in the reviewed path includes AWT Shape/Graphics2D/BasicStroke and `DBPreferences` access ([PFMRenderPipe.java:3–35](https://github.com/SonarSonic/DrawingBotV3/blob/0e7c900638def19b9a8d16445099f3f1129aee52/src/main/java/drawingbot/pfm/helpers/PFMRenderPipe.java#L3-L35)); `PlottingTools` also references task, drawing, and transforms.

Proposed first scope:

- Pure JVM Kotlin core with explicit settings, mutable raster/reference arrays, clip mask, cancellation/progress hooks, seeded RNG, darkest-tile cache, active line sampler/scorer, and the required Bresenham primitives. Output ordered pixel-coordinate polylines/squiggle boundaries and sampled ARGB; no JavaFX, application singleton, IO, or Android dependency.
- Start with the constant-radius, rendered-pen-width `1F` ARGBY/Bresenham backend. This is a **restricted compatibility scope**, not parity with all canvas configurations. Additive/Graphics2D antialiasing and arbitrary width are deferred until an oracle demonstrates a portable equivalent; do not silently substitute Android Canvas.
- Port only required helpers after checking their own attribution. `BresenhamHelper.java:182` explicitly credits Zingl; retain that provenance and review the referenced helper's license before copying it. No new dependency is proposed in this memo.
- Keep source algorithm and embroidery adapter independently testable. The adapter maps processing pixels to physical size using the existing photo policy and existing running-stitch/Stroke, StitchGroup, and StitchPlan conversion. Pen lifts become explicit disconnected runs with existing trim/jump/lock processing. Do not sew one stitch per raster sample or silently connect separate squiggles.
- Reuse `PhotoPreparationPolicy` for raster size and hoop-based width limits. Toggle-off must call the existing `ColorDrawingPipeline.trace/generate` unchanged. Toggle-on needs the pre-trace raster, because region polygons alone have already discarded tonal texture. Existing paths: `engine/.../inkstitch/svg/image/{PhotoPreparationPolicy,ColorDrawingPipeline}.kt`, `engine/.../inkstitch/stitches/RunningStitch.kt`.
- Multicolor thread mapping remains a separately approved adapter decision: preserve Free sampled ARGB, then evaluate reuse of the existing quantizer/thread resolver. Independent per-palette luminance masks are another possible experiment, **not verified upstream Free behavior**. Do not implement Premium Colour Match or claim its equivalence. Color grouping/reordering also needs its own visual and sewing tests.

The final generated pattern must pass existing SewoutCheck, PecViewportCheck, and PES export guards. P1–P8 remain mandatory: top-left/nonnegative export, hoop `0..dimension-1` (`0..999` for 100mm), exact header extent, no zero-length jump/stitch, consecutive same point at most 2, existing half_stitch locking, generated density limit 15 per 0.5mm cell, maximum stitch 12mm. Plotter line density is **not** an embroidery density guarantee. A rejection remains a rejection; no threshold relaxation or imported-pattern exemption is proposed.

## Proposed comparison and acceptance procedure

No oracle was executed in the initial research unit. The following was its proposed plan; execution was subsequently authorized on 2026-10-27, with results below.

1. Request upstream traces at the pinned commit, or later run an explicitly authorized reference harness. Use repository-owned/generated small raster fixtures: white/black, gray ramp, isolated dark dot, horizontal/vertical/diagonal strokes, equal-tone tiles, transparency, edge clipping, and a small multicolor drawing. Include dimensions below 10 and nonmultiples of tile size. Save effective settings, raster/reference hashes, seed, pen width, backend and clipping with every trace.
2. Compare intermediate stages **exactly**: RNG draw sequence; tile sums/selected pixel; ordered candidate endpoints; prefix counts/scores/winner; per-line erase amount; changed pixels; sampled ARGB; squiggle boundaries; termination reason. Report first mismatch index and values. Default whole-image output must match ordered coordinates/count/hash before any stitch resampling or pen optimization; screenshots alone are insufficient.
3. Repeat fixed-seed jobs and concurrent independent jobs to prove reproducibility. Exercise shading/unlimited/equal bounds separately from the first restricted default implementation. White input must terminate without a line; unreachable/fully clipped input must terminate without invalid coordinates. Timing/memory are measured later; mobile latency is currently unconfirmed.
4. Test the embroidery adapter separately: pixel→mm scaling, palette mapping, short-run handling, locks/trims and travel; round-trip PES through PesReader; assert all existing gates including density and viewport. Preserve the raw plotting trace so a sewing adaptation does not masquerade as upstream mismatch. Toggle-off has exact existing pattern/PES regression tests.
5. Only after code comparison and safety assertions, provide a small physical sew-out sample to judge texture, thread accumulation and color layering. Visual similarity to PE-Design and acceptable fabric behavior remain unconfirmed; upstream is a plotting source, not a sewing-quality oracle.

Decisions recorded at initial review: approve the restricted default raster backend; choose and verify a multicolor adapter; authorize an upstream oracle source/execution route; select processing resolution and running-stitch settings from existing policy and measured sew-out results. Subsequent approvals and pending items are recorded below. This memo introduces no new stitch limits or UI settings.

## First implementation unit (2026-10-27)

`engine/.../texture/{SketchLines,SketchRaster,SketchLineSampler}.kt` now implements the approved restricted core. Public entry point: `SketchLines.render(width, height, argb, clipMask, settings, isCancelled, onProgress)`. It copies input data and returns ordered plotting lines with sampled original ARGB, squiggle indices, typed termination and raw progress. Coordinates are integer processing pixels; output is deliberately not an EmbPattern or PES. `SketchSettings` uses registered defaults; erase bounds and line/squiggle bounds normalize like upstream setup. Constant radius/pen width 1 are fixed by scope, not exposed settings.

The sampler preserves the active integer trigonometric offsets, prefix scoring and axis bias. The raster preserves RGB addition/clamping, truncated perceived luminance and incremental tile averages. Java `Random` bounded methods are delegated directly, including equal/reversed-bound wrappers; no replacement PRNG or OpenJDK implementation is copied. These bounded methods require JVM 17 in this first pure-JVM unit. Android runtime/desugaring support remains unconfirmed and must be resolved before any app integration; no app code calls this API yet.

| Deliberate scope/difference | Reason / verification status |
|---|---|
| Pixel mask instead of AWT Shape; no application transforms or hard clipping geometry | Caller supplies the already sampled integer soft-clip mask. No JavaFX/AWT dependency. Geometric mask construction is outside this unit. |
| Fully clipped raster returns `NO_DRAWABLE_PIXELS` before averaging or selecting a tile | Prevents division-by-zero/invalid-coordinate traversal; regression test requires no lines. |
| Cache initialized once per render instead of lazily on first search | Same x-major tile arithmetic; no shared state. |
| Typed cancellation and progress observer instead of desktop PFMTask callbacks | No application/task dependency. Raw default progress formula preserved, including its zero-density/zero-limit NaN behavior; callers must not interpret NaN as completion. |
| No additive/composite raster, width/radius variation, pen optimization, palette mapping or embroidery conversion | Approved first backend only; no claim of equivalence outside that scope. |
| No official execution comparison | User permission pending. Local contract tests are not an upstream oracle. |

Zingl license review completed: the linked helper LICENSE is MIT, copyright `(c) 2020 zingl`; full permission/warranty text is retained under `engine/src/main/resources/licenses/thread-texture/`. DrawingBot GPL and source attributions are recorded in `THIRD_PARTY_NOTICES.md` and each ported source header.

## Authorized original-source comparison (2026-10-27)

User authorization explicitly permitted receiving the pinned sources only under `/tmp/myembro-dbv3-oracle/` and compiling/executing a minimal line harness, excluding JavaFX/application execution, installation scripts and additional network dependencies. That scope was followed. Original source files, compile-unit adaptations, harness and classes remain in `/tmp`; no original Java source or JAR is committed.

The harness executes the original full PFMSketchLinesBasic/AbstractSketchPFM, active sampler/scorers, ARGBY/RawData and darkest-area cache with observation-only trace insertions. It selects the original Bresenham/luminance/color/erase helper bodies and replaces desktop task/canvas/geometry boundaries with restricted glue. This is an original algorithm oracle **after raster preprocessing**, not the full desktop application. Exact source hashes, adapter/stub boundaries, commands and event format are recorded in [the fixture provenance](../../engine/src/test/resources/drawingbot-oracle/README.md).

Ten repo-owned synthetic cases were run with registered defaults and seed 0: white, black, gray ramp, one dark dot, horizontal/vertical/diagonal lines, equal-tone tiles, a 7×6 raster and a 23×13 remainder raster. Traces include input hash; RNG order; tile average bits; selected pixels; candidate coordinates; prefix counts/score bits; final winner; erase amount; every pixel write; sampled original ARGB; squiggle boundaries; progress bits and termination reason.

`./gradlew :engine:test --tests '*SketchOracleTest' --tests '*SketchLinesTest'` passed 29/29. `python3 tools/check_thread_texture_oracle.py /tmp/myembro-dbv3-oracle/out engine/build/texture-oracle-port` reported **10/10 PASS, 46,043 events and 318 lines byte-for-byte equal, first difference: none**. No line-generation fix was required. Optional trace hooks are the only production changes in this unit; the persisted goldens are text traces only. Normal CI compares the Kotlin port with frozen text and never downloads or executes upstream.

Limits remain: these results do not establish parity for clipping geometry, alternate seed/settings combinations, raster preprocessing, composite/variable-width rendering, full-app optimization, multicolor embroidery mapping, PES safety or actual sew-out quality. The next embroidery adapter remains a separate unit.
